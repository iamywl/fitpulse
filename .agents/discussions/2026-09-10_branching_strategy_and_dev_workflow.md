# 에이전트 간 디스커션 기록 (2026-09-10)
## 주제: 개발 전용 브랜치(`develop`) 신설 및 배포 브랜치(`main`) 운영 격리 원칙 수립

### 1. 배경 및 사용자 요구사항
- **사용자 지시사항**:
  > "개발용 브랜치 만들고 거기서 나랑 대화를 통해 개발을 진행하고 현재 브랜치는 내가 배포하라면 배포하기 위해 머지하는 브랜치로 사용할 거니까 이 내용 에이전트 파일에 반영해주고, 개발 진행해"
- **목적**:
  - `main` 브랜치에 불완전하거나 실험적인 코드가 실시간 푸시되어 Netlify 배포 환경에 예기치 않은 영향이 가지 않도록 격리.
  - 사용자와의 모든 일상적인 대화, 세부 개발, 테스트, 피드백 루프는 독립된 `develop` 브랜치에서 안정적으로 진행.
  - 사용자가 명시적으로 "배포해줘"라고 지시할 때만 `develop`을 `main`에 머지하여 프로덕션 배포 트리거.

---

### 2. 브랜치 운영 정책
1. **`develop` 브랜치 (기본 작업 브랜치)**:
   - 현재 작업 브랜치로 체크아웃 완료.
   - 모든 컴포넌트, 서비스, 로직 작업 및 일상 커밋은 `develop`을 대상으로 수행.
2. **`main` 브랜치 (프로덕션 배포 전용)**:
   - 사용자가 "배포하라"고 승인/요청할 때만 `git checkout main && git merge develop && git push origin main` 실행.
   - 평상시에는 직접 커밋 금지.
